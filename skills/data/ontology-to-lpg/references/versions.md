# Versions of the method

Read it when a project pins an earlier version of the guideline, or asks what changed. Each version keeps the earlier rules unless a line below says otherwise.

| Version | Where | What it changed |
|---|---|---|
| 2 (October 2026) | the guideline folder in the enterprise-people-graph repository, commit `cd63e12` | Five design rules and a five-step core path, with optional add-ons; RDF 1.2 reifiers for link properties. |
| 2.1 (October 2026) | same folder, commit `e7b09e8` | Rule 4 got two options: 4a, qualified-relation nodes, the default, and 4b, RDF 1.2 reifiers. The flatten step became 4b only. RDF 1.2 status corrected to Candidate Recommendation. |
| 2.2 (October 2026) | same folder, commit `8ce9ada` | From the first full run: SHORTEN instead of MAP; the full shapes before the load and a subset in the graph; `inferred.nt` without the reasoner's declarations; the round trip compares values, not spellings; CI checks a committed report; plugin jars pinned by checksum. |
| 2.3 (this skill, 23 October 2026) | `ontology-to-lpg` | See below. |

## What 2.3 adds over 2.2

From the projection of a multi-module enterprise ontology, every released package at once, in October 2026:

1. **The guideline becomes this skill.** Repositories that kept a copy of 2.2 point here instead. The examples move to the library domain.
2. **Inputs are released packages** (`inputs.md`, rules 1 and 2): each at its newest version, pinned by hand and checked against the release folder, each with its own shapes, plus the whole-graph shapes.
3. **The rules cover every namespace you own whose terms are predicates or classes**, each with a fixed prefix, and the standard namespaces are registered too (`inputs.md`, rules 3 and 4).
4. **Release exceptions are a mechanism, not a checklist line** (`inputs.md`, rules 5 and 6): keyed by the checker's exact message, each with its fix, failing on a stale entry. `scripts/check_projection_rules.py` implements it.
5. **Rule 4a counts an inverse link as an end** and requires exactly one such link per node (`design-rules.md`, rule 4). Every qualified-relation class is registered with its ends.
6. **`sh:pattern` and literal `sh:in` lists leave the graph**, found by testing n10s 2025.06.1 against the source (`pipeline.md`, rule 13); `sh:in` lists of IRIs stay. At first each constraint kind was tested in the engine with a pass and a fail case, and `scripts/in_graph_shapes.py` generated a subset; item 24 replaced both: every compiled row now gets its own case, and the gate is the engine's readback.
7. **Rule 1 and Rule 2 say how annotation properties and lists are stated:** an annotation property needs a kind and a cardinality but no range; an optional list says `sh:minCount 0`.
8. **Rule 3 says why prefixes matter in SHORTEN mode:** n10s names a term by its namespace's prefix and invents a numbered prefix for an unknown namespace.
9. **Running the projection** (`running.md`): CI runs check and serialise only; the report's fingerprints cover every shape file; `inferred.nt`, the manifest and the report are committed together; the container is removed with `docker rm -f -v <container>`, and its run folder with the password file deleted, once `check-report` has passed, or when the run stops.
10. **Scripts for the check, reason and serialise steps** (load and verify followed in item 15): `validate_data.py` (pySHACL and the refusals) and `build.py` (the reasoner's merged input, the N-Triples files, the inferred filter, the generated load script, the manifest and the report check), with the jar checksums and a `docker run` line bound to localhost.
11. **Exact definitions where 2.2 left room:** the byte sort order and the input fingerprint (`pipeline.md`, rule 5); the decimal and language-tag refusals (rule 3); which predicates load as arrays (rule 10); which file `onto.import` reads and what success is for the shapes import (rule 11); the export query and the schema rows it must leave out (rule 16); emptying the database between loads on Community edition (rule 17).
12. **Fixes found by running 2.3 end to end:** ROBOT needs `--include-indirect true` to infer anything an individual's direct type does not already say (rule 4); array sorting is restricted to `:Resource` nodes, because sorting n10s's own configuration nodes corrupts them (rule 10); the export returns a tagged literal's text with `literalLang` set (rule 16).
13. **The in-graph subset follows the n10s source:** it also drops `sh:datatype` values n10s throws on, `sh:and`, `sh:or`, `sh:xone` and a literal `sh:hasValue`, and keeps a property shape a targeted shape still uses (rule 13). Rule 14 gives a fail case for each constraint kind left in the graph. (Replaced by item 24.)
14. **The checker is stricter:** a datatype range must be a row of the XSD to Cypher table; a cardinality counts only on an applied shape; every namespace a class uses needs a prefix; each qualified-relation end needs an exact shape; release exceptions waive only Rule 1, 2 and 5 gaps; the Rule 4 option and its reason are read from the configuration.
15. **A load-and-verify script, `load_verify.py`**, from two more test runs (one on the library example, one on a private multi-module ontology): it loads with status checks, compares the shapes import with `listShapes()`, commits and restores the mutant, diffs the export with schema rows left out, and compares two hashed loads, with the hash fully specified. Its first fail cases were one per constraint kind, with kinds left without a case listed; item 24 replaced that with one case per compiled row.
16. **A round-trip fix:** n10s exports a tagged string that holds a newline as `xsd:string` `"text@en"` with no `literalLang`; the diff now splits the tag with a DOTALL pattern (`pipeline.md`, rule 16).
17. **Rule 2 counts every target kind SHACL applies**, and shapes reached through `sh:node`, `sh:and`, `sh:or` and `sh:xone`; it checks only the properties the data uses. Release-exception keys may use full IRIs.
18. **The in-graph subset keeps only the SHACL terms n10s reads,** so `sh:lessThan`, `sh:lessThanOrEquals`, `sh:equals` and the like are dropped, as are IRI-named SHACL-SPARQL nodes and deactivated shapes. (Replaced by item 24.)
19. **Running details:** the plugins mount must be writable and open to the container's user (the image writes `apoc.jar` into it); the image is pinned by digest; the start wait fails on an exited container or an error; the manifest records paths relative to its own folder.

## Where 2.3 differs from the method as practised

- **Annotation properties need no range here.** The build behind 2.3 required a single range for every owned predicate, annotation properties included; this skill follows the `ontology` skill, where an annotation property takes neither a domain nor a range.
- **Rule 2 checks only properties the data uses.** The build did the same; the first draft of 2.3 also checked declared but unused ones.

20. **From review round 2 (the subset parts replaced by item 24):** the in-graph subset then ran n10s's own shape queries with rdflib (item 24 made that an advisory prediction); every script stops under Rule 4b; predicates inside property paths and superproperties need a prefix; a pin must be `X.Y.Z`; `docker rm -f -v` removes the run's volumes, and the container stays up until `check-report` passes. The manual cases and listed kinds this round introduced were removed by item 24.

21. **From the fourth quick check (replaced by item 24):** this round made drop reasons name only the conditions that failed, and added a node-level `sh:class` kind, the carry-over of hand cases between runs and a `<report>.previous` file for a failed run. Item 24 removed the kinds, the carry-over and the `.previous` file.

22. **From the final run on a real multi-module ontology:** `build.py check-serialised` checks the step 4 gate; `load_verify.py --container` (or `$LPG_CONTAINER`) names the container in its next steps; `running.md` rule 5 keeps the run's container name, port and password in a mode-600 `run.env`, because agent tools start a fresh shell per command, and its start check returns instead of exiting the shell; the shapes list is built from the configuration's pins; `own_namespaces` needs only namespaces whose terms are predicates or classes; the pipeline's sections carry SKILL.md's step numbers.

23. **From quick check 6:** `check-serialised` rejects lines that are not one triple and inferences already asserted, and runs in CI; printed commands are shell-quoted. Its rules on kinds, `kinds_without_case`, carried hand cases and reports set aside as `invalidated` were removed by item 24.

24. **The engine is the gate (replaces the subset rules of items 13, 18, 20 and 21, and the carried and set-aside reports of items 21 and 23).** `in_graph_shapes.py` now leaves out only what makes n10s throw or judge valid data wrong, including value terms on an inverse path, which n10s checks the wrong way; its prediction of the compiled rows is advisory. `load_verify.py` reads `listShapes()` back after the import, compares it with the shapes file by target, path, param and value, and reports every constraint n10s did not compile (`pipeline.md`, rule 13). It plans one fail case per compiled row; each case creates its own node, so it needs no matching data, and passes only on its focus, path and component (rule 14). A row without a generated case fails the run until `--manual-cases` gives one; nothing is carried between runs (`kinds_without_case`, `manual_cases`, the carry-over and `.previous` are gone). The report is fail-closed: it is written, by a rename, only when every check passed, and `check-report` requires `passed: true` (`running.md`, rule 3). `check-serialised` accepts a line only when it is exactly one N-Triples triple, without comments. Add-ons H (`GRAPH TYPE`), I (copy to Aura or another Neo4j) and J (a SPARQL 1.1 triple store) are new; H and I were run on Aura Free and J on Jena Fuseki 6.2.0. `references/multi-store.md` records the plan for one release in several stores, with add-on K (Databricks) planned. From the full review of the redesign: `copy_graph.py` copies only a graph whose hash equals a passing report's (`--report`, add-on I); every printed value is shell-quoted; a closed shape's compiled ignore-list must equal the file's; minimums are tested one value short; the store report is fail-closed like the projection report; the graph hash writes a date with its type; GRAPH TYPE takes its list types from the load's multivalued list and writes no empty node type; `check-report` requires a case for every compiled row. From the second review: every printed value goes through `scripts/shell.py` (a test reads every script's syntax tree), and `build.py cypher` and `graph-type` write to `--output`; `check-report` fails when `compiled` is missing; `copy_graph.py` and `triplestore.py` recheck a report with `build.report_earned` instead of trusting `passed`; a closed shape's ignore-lists must match the compiled rows both ways. From quick check 10: the print check is strict (every positional and keyword argument of every print or stdout/stderr write, no exemptions, and the three line-building helpers checked by the same rule); `copy_graph.py` compares the two databases by their `db.info()` id; `pipeline.md` rule 5 writes the manifest after `check-serialised` and the second SHACL run.

## Migrating a project from 2.2

Expect the checker to report two things a 2.2 project did not see:

- **A missing `xsd:` prefix.** Rule 3 now counts datatype ranges, so the namespace of every `rdfs:range` datatype needs a prefix in the configuration.
- **A stale release exception on an annotation property.** 2.2 builds required a range on annotation properties too; 2.3 does not, so an exception listed for an annotation property with no range no longer occurs and fails as stale. Remove it.
